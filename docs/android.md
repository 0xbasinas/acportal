# Android implementation

The Android project is in `android/universal-acp`. Build with `./gradlew :app:assembleDebug` and run JVM tests with `./gradlew :core:protocol:test :app:testDebugUnitTest` (use `gradlew.bat` on Windows). SDK 36 is required. Run Gradle with JDK 21 on this Windows machine; source/toolchain targets remain configured in the build files. Minimum Android version is API 26.

## Module architecture

Use Kotlin, Compose and Material 3 with coroutines/Flow. Keep `core:protocol` independent of Compose and Android framework classes so its reducer and JSON-RPC tests run on the JVM. It must retain unknown ACP update variants and render a compact fallback rather than rejecting a future agent.

The independent JVM module `core:protocol` supplies wire models, the session reducer and a bounded diff algorithm. The app's `transport` package supplies:

```kotlin
interface AgentTransport {
    suspend fun connect()
    suspend fun disconnect()
    suspend fun send(message: ByteArray)
    fun messages(): Flow<ByteArray>
    fun connectionState(): Flow<ConnectionState>
}
```

WebSocket uses OkHttp with TLS validation, auth headers, ping, deadlines and a single reconnect owner. It feeds the ACP router. Future connection strategies can be added behind the transport interface without changing session logic.

The app's `data` package owns the management API, active session connections and reducer pipelines. ViewModels expose screen state and actions. Application-scoped repositories keep sessions running when navigation changes; Compose disposal does not stop the host agent. An application dependency graph wires these services.

The `storage` package uses Room 3 for profiles, credential aliases, recent combinations, session/agent metadata, bounded page preferences, drafts and optional bounded message cache. Schema version 3 and prior versions are exported with additive migrations. DataStore holds theme and cache preferences. Credential bytes are kept out of both.

The `security` package uses Keystore AES-GCM encryption, unique nonces and encrypted bearer credentials in the app's no-backup directory. Room stores aliases only. OkHttp validates TLS using system trust. Optional biometric access is not implemented yet.

## Screens and visual system

Use Hosts, Sessions and Settings as the only primary destinations. Phone navigation uses a bottom bar; larger windows can use a rail and a constrained reading width. The session screen gets the available space. Keep touch targets at least 48dp, use insets and IME padding, and preserve text scaling.

Follow the user's 16 screen mockups documented in `ui-reference.md`. Use a near-black default theme, neutral surfaces, white primary actions, green online indicators, 24dp page gutters and compact text. Keep a rounded text-only phone navigation pill and a rail on wide windows. Use simple rows, inset user messages, unboxed agent messages, compact tools and a permission bottom sheet. Light and system appearance remain available. Show loading, offline, empty and retry states as part of each screen.

Hosts show address, connection status and available agent count. Host details separate workspaces, agents and active sessions. The agent picker renders registry names and availability, never a hard-coded provider list. Workspace browsing stays inside host-allowed roots and remembers recent combinations.

Session content is a sequence of typed events: user/agent text, agent-provided thoughts, tool activity, plans, permission requests and errors. Thought blocks start collapsed and require explicit expansion. Only `agent_thought_chunk` content supplied by the agent is retained; no hidden content is requested or inferred. Text chunks merge within the same role and message ID. Non-text thoughts use the shared content viewer after expansion. These blocks follow the existing message-cache setting, history retention limits and local-removal controls; exports label them Agent thoughts separately from answers. The event is defined in the [ACP session update schema](https://agentclientprotocol.github.io/typescript-sdk/types/SessionUpdate.html).

The conversation header shares the Sessions page's activity rules: stopped/connection state, replay, pending approval, working turn, then ready. A disconnected cached working turn cannot appear live. The thought/activity increment passed 38 protocol tests, 22 app unit tests, build/lint and eight emulator checks, including the full conversation view. The reviewed screenshot is `.local/screenshots/agent-thoughts.png`. Real-agent thought events, physical-device lifecycle and accessibility acceptance remain open.

The composer offers multiline text, send or stop, and one secondary-action menu. Attachments appear only when prompt capabilities permit their content type. Model and mode selection come from session setup/update options. Agent identity is display metadata, never a feature switch.

Permissions display the tool title, raw operation details when available, workspace and supplied choices. Host-generated filesystem permissions show "Host permission needed" and offer a proposed-diff review before approval. Do not synthesize an "allow for session" option when the request did not offer it. A pending request remains visible after replay and can be answered exactly once.

Expanded tool diffs offer View changes. The full Changes page selects among cached tool changes, preserves source line numbers, highlights additions/removals and uses basic lexical colors for common source/configuration formats. It collapses unchanged sections to three lines around edits; sections can expand individually or all at once and collapse again. Previous/next buttons jump between modifications. Rows scroll horizontally, and the list renders the whole available file without the inline preview's 1,000-line ceiling. A split view is available at widths of at least 700 dp. Replacements retain separate old/new rows in split view rather than pairing unrelated lines. Pending permission diffs offer the same full-page review in a dialog; closing it leaves the decision unanswered.

Diff calculation runs off the main thread on the full page. It removes equal prefixes and suffixes before the bounded LCS comparison, so a large unchanged file or small middle edit does not become a whole-file replacement. Changed regions beyond the comparison bound use a coarse linear fallback. Syntax coloring is a lightweight line lexer, not a complete language parser. Terminal output remains collapsible, bounded monospace blocks; no interactive emulator is required for the MVP.

Four dedicated JVM diff tests cover empty files, context expansion, edit retention and large-file matching/line numbers. Phone UI checks cover modification/file navigation and expanding then collapsing 1,005 unchanged lines. A separate 1,280-by-800 emulator run verifies split/unified switching. The permission suite verifies full review closes without choosing an option. The authenticated mock-host flow opens the agent's actual diff and returns to the conversation before completing terminal, reconnect and local-copy checks. ## Capability mapping

Read/write/terminal toggles are saved per host and normalized workspace path, including Windows canonical-path and case handling. New and explicitly loaded sessions send the saved policy in the host API request. The host advertises exactly those client capabilities and rejects disabled callbacks independently of agent behavior. Effective access is included in session metadata and retained across host restart. Old records use the previous all-enabled behavior for compatibility.

Access changes apply to the next agent process, not a WebSocket reconnect. The thread page displays both saved choices and the current session's effective policy. Host writes and terminal creation still require explicit approval; disabling them prevents requests from reaching the permission queue. These settings do not sandbox agent-owned tools or MCP processes. Two JVM normalization tests, two Compose policy tests, a reopened-storage test and the authenticated phone-to-host flow passed. The session menu opens full Agent details, Session options, Connection details and Connection logs pages. Connection controls act on the current WebSocket without terminating the host agent or resending prompts. Manual disconnect remains detached until explicit reconnect. Diagnostics keep the latest 200 fixed lifecycle messages in memory, with filters, paused/live viewing and clipboard copy. They exclude payloads, credentials, raw network exceptions, prompts and agent output.

## Attachments

The composer's secondary menu also opens Prompt history. It lists up to 20 distinct submitted text prompts, newest first, from this conversation's retained timeline. Selection copies exact text into the draft and does not send; replacing nonempty different text requires confirmation. Current attachments stay selected, while past attachment content/references are excluded. Attachment-only submissions, agent echoes and older cached entries without submitted-text metadata are omitted because their original text cannot be reconstructed safely. History has no separate storage: optional message caching, timeline eviction and Remove local copy govern its retention. Removing a local copy also closes the sheet and clears a pending replacement choice.

The composer offers native document selection for files, images and audio when the agent advertises the corresponding ACP prompt capabilities. Context URI references remain available for host-accessible resources. Selected phone files stay in memory until explicit Send; navigation within the live session preserves selection. Accepted prompt echo clears the submitted selection, while failed submission retains it. Process death requires selecting files again. Attachment payloads and phone document URIs are not persisted in conversation history, diagnostics or saved instance state.

Selection is bounded to four attachments, 256 KiB per file, 384 KiB combined attachment JSON and 512 KiB complete prompt JSON. UTF-8 files become embedded text resources, other files become embedded binary resources, and image/audio blocks carry base64 data and MIME types. The standard ACP content blocks reach the agent unchanged. Capability checks do not guarantee support for every media codec.

Four protocol tests, a transport observer test, three loader device tests, two composer control tests and one authenticated host integration test passed. The native-picker navigation test also passed: selecting a file leaves the turn idle, returning from Agent details retains it, and attachment-only Send starts the turn and clears the accepted selection. Rust's typed ACP request and lifecycle test verifies media/resource forwarding. Remaining product work is tracked in `TODO.md`.

## Received content

Conversation chunks and expanded tool results share a viewer for the standard [ACP content blocks](https://agentclientprotocol.com/protocol/v1/content). Images open a native preview on explicit selection. Decoding runs away from the UI thread, rejects images above 64 million source pixels and samples previews to at most 1,024 pixels per dimension. Audio starts only after Play, uses embedded bytes in a private temporary file, requests transient audio focus, and releases playback/files on completion, error, focus loss, backgrounding or disposal. Leftover temporary audio files are removed at app startup. No agent-provided URI is used as a media data source.

Embedded text can be expanded and saved; the inline preview marks its 64,000-character limit. Binary resources and media can be saved through Android's document picker. The chosen block is captured before opening the picker so subsequent tool updates cannot substitute different bytes. Decode/save actions accept at most 768 KiB of embedded bytes. Unsupported codecs and malformed data show an error while retaining inspectable content. Resource references can be copied. Only credential-free HTTP/HTTPS references offer Open link, which asks before launching another app. Links are never fetched automatically.

Incoming content, including agent-replayed user media, follows the optional conversation-cache setting. Submitted client prompts continue to record attachment labels rather than the outgoing payload. Transcript export includes embedded text and resource identities, with a note for media instead of inline base64. Unknown content variants remain in bounded state and show a visible fallback. Timeline retention uses a conservative 8 MiB estimate and 2,000 items; long streamed text retains its latest 1 Mi characters. Eviction marks a history gap. Auxiliary state and queued frames still need separate byte budgets.

Session title and last-update patches preserve omitted fields and honor explicit nulls. The live header and saved session rows use reported titles when available. Agent details shows reported context-token counts and cumulative cost, without inventing missing values. Usage updates replace the previous snapshot. Optional message IDs distinguish consecutive streamed messages. Title/timestamp metadata is retained in normal cursor checkpoints even when message caching is disabled.

This increment passed 31 protocol tests, 15 app JVM tests, build/lint, six content UI tests, two native decode/save tests, an authenticated mock-host-to-conversation test and three loader checks. ## Error recovery

Conversation errors have working dismissal and distinguish agent requests, sign-in failures, invalid host events and stopped sessions. Dismissal only clears the displayed error. It preserves messages, prompt state, selected attachments and pending permissions. A replay completion clears a connection-recovery error without hiding an unrelated agent error. Stopped-session state survives dismissal, disables submission and prevents reconnect to the dead process.

WebSocket HTTP 401/403 stops reconnection and offers Pair again with the saved address and connection name. The user supplies a fresh code; the code is kept out of saved instance state. Re-pairing replaces credentials and closes old live phone connections through the existing repository path. HTTP 404 offers Open Sessions. HTTP 409 shows the controller conflict and permits an explicit reconnect after the other client disconnects. Other transient failures retain exponential backoff. Reconnect never resubmits a prompt.

Pending permissions are reconciled from the host's replay snapshot. `replay_start` clears the previous actionable set and starts a separate snapshot accumulator. Historical journal requests may appear during replay, but decisions stay disabled. Each `pending_permission` snapshot fills the accumulator; `replay_complete` replaces the actionable set with that snapshot, including an empty set. A missing or evicted acknowledgment therefore cannot leave a historical request actionable. Repeated snapshot entries are deduplicated by request ID. Ordinary live permission events continue to update the pending set after replay.

The repository requires a connected, non-replaying, non-stopped session and an exact match against its current permission before sending a choice. Detached, resolved or changed requests fail locally without sending. The host remains responsible for final decision validation if a request changes after the local check. Closing a session clears the snapshot accumulator. This increment passed 40 protocol tests, 22 app unit tests, debug build/lint and eleven device checks, including authoritative snapshots through two mock-host reconnects and full conversation permission gating. Process-death and physical competing-client acceptance remain broader checks.

Failed host details, workspace browsing, session opening, MCP reads and workspace-policy reads expose an explicit Retry action. Creating sessions, sending prompts, pairing, permission decisions and other writes have no automatic retry action. Their existing controls remain the way to submit another action intentionally.

While a saved session opens, or if its metadata request fails, navigation displays its local conversation and draft rather than an indefinite Opening session placeholder. Saved conversation labels the view; sending, cancellation and cached permission decisions are disabled. Display-only state clears processing/replay flags and pending actions without rewriting the stored replay cursor or history. Draft edits still use the normal Room path. Connect to host explicitly retries opening; a successful open replaces the saved view with the live session. Removed local records show a Session unavailable page with Back. Interrupted sessions retain the explicit resume page and offer View saved conversation. That separate local route performs no host open/resume and returns through Session actions.

Live and saved views share the bounded Markdown exporter. Export transcript captures the selected state before opening Android's CreateDocument contract. Saved messages and explicitly supplied thought content are exported; unsent drafts, pending decision data and raw credentials are excluded. The interrupted-history navigation test intercepts the document contract with a temporary app-owned URI, checks the written content and privacy, confirms no live ViewModel session or changed host status, and returns to explicit session actions. Together with saved-view, permission and UTF-8 writer regressions, eleven device checks passed. Provider-specific selection, interrupted-history process death and large-history export remain broader acceptance.

The conversation applies keyboard insets to its page container so the composer stays above the keyboard. The longer offline explanation is hidden while typing; Saved conversation remains visible. Eleven emulator checks cover saved messages/drafts, inactive pending decisions, empty cache, controlled HTTP 503 navigation, keyboard-visible composer, draft-preserving connection recovery and existing recovery/history controls. ## Verification gate

Room schema 3 adds one `ui_state` row for the main page and Sessions archive/active/search preferences. Search is limited to 512 characters. Page and filter updates use separate transactional column updates so concurrent saves preserve both. Navigation waits for the initial stored preference before constructing its back stack. Navigation 3 continues to manage the serializable saved back stack for Activity recreation. Fresh launches restore only Connections, Sessions or Settings, rather than reopening a session or action route. Pairing codes, selected attachment bytes, permission actions, confirmation dialogs and unsaved configuration edits are excluded from this durable preference row.

Device tests verify the additive 2→3 migration retains agent catalogs, chained opening from schema 1, concurrent writes, invalid route/search rejection and database reopen. Actual UI navigation sets archive/active/search choices and retains them across tab switches. A separate instrumentation invocation after a verified app-process stop restores the selected Sessions page and those choices and confirms no live session was opened. Each fixture restores the earlier page preferences. Full-session process-death recovery, page scroll/expanded activity acceptance and physical-network checks remain open.

Room schema 2 adds a per-host discovered-agent catalog. Successful discovery replaces the whole list, including optional executable/version/reason fields, with its check time. The serialized catalog is limited to 1 MiB per host and contains only the Android discovery model, excluding registry environment variables or credentials. Removing a host cascades its catalog. Registry list/detail pages can inspect saved metadata while refreshing or after failure; they label its check time and previous availability and disable New session until fresh discovery succeeds.

The exported version-1 schema is retained and Room generates the non-destructive 1→2 migration, following the [Android Room migration workflow](https://developer.android.com/training/data-storage/room/migrating-db-versions). Migration tests verify preserved hosts/credential aliases, session state/drafts/archive flags and recent combinations, then validate catalog reopen, replacement and host-specific deletion. Eight targeted device checks, 22 app unit tests and debug build/lint passed. Installing over the existing paired emulator app did not clear data. Full-session process-death and physical-network acceptance remain open.

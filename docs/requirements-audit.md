## Acceptance gates still open

1. **Protocol universality:** run a real Goose workflow with read/write, rejected and approved permissions, complete diff review, tests/terminal callbacks, cancellation and explicit resume. Verify adapters/custom commands through the same protocol path. Do not infer compatibility from executable discovery or a no-tools prompt.
2. **Pages:** use all 16 mockups and the screen checklist in `screen-acceptance.md`. Check each screen's spacing, typography, touch targets, dark/light, loading/error/empty, keyboard, large fonts, landscape, small/large phone and tablet behavior. Current targeted emulator checks are partial evidence.
3. **Product state acceptance:** Room schema 3 persists main-page and Sessions filter/search choices, with tested migration, concurrent saves and cold restoration. Agent metadata also persists. Thought blocks display only content explicitly supplied by agent events, collapsed until expanded. Prompt history selection and discovered-agent diagnostics are implemented; broader scroll/expanded-activity, lifecycle and cross-platform acceptance remains open.
4. **Recovery:** physical trusted TLS, token renewal/expiry/revocation, network switch, offline cache, competing controllers, background/lock/unlock and app process death. Preserve host processes and pending decisions, detect history gaps and never repeat a prompt automatically.
5. **Resource and security boundaries:** byte budgets for auxiliary Android state/queues and host request cache, large-content stress, Windows launch/cleanup assignment gap, Unix escape/crash cleanup limits, filesystem concurrent-write/metadata limits, and secure storage permissions. Existing host callback policies are not an OS sandbox.
6. **Operations:** complete doctor diagnostics and bounded host logging; check Rust minimum, native Linux/Make, Docker, clean Windows builds and installation/configuration instructions. Do not treat supplied recipes as successful execution.
7. **Release:** compile/test appropriate targets after changes, review dead code, preserve source/test evidence and update docs. Build/install a signed release artifact and record the full acceptance results before claiming production quality.

Optional/later features (QR, biometrics, fork/new transports, slash commands, full terminal/IDE, cloud accounts and marketplace) are not prerequisites for this implementation pass. Optional delivery-journal persistence requires a product decision; bounded replay and visible gaps are already part of the current recovery contract.

## 9 October 2026 — native background host and explicit soft reload

Implemented `start --background` and `daemon start/status/stop/reload` with protected local capability authentication, bounded loopback control messages and exclusive ownership. Windows launches through CreateProcessW without inherited handles; Unix uses literal arguments and setsid. Stale records never authorize killing a saved PID. Graceful stop uses the existing agent cleanup boundary. This is a detached user process, without OS service installation or automatic restart.

Reload validates config and registry before atomically publishing one future-launch snapshot. Registry, workspace roots, review and eligible runtime settings can change; listener/TLS/token settings, storage, frame size and logging require restart. Existing sessions and in-flight launches retain their settings. A replay fixture verifies an authoritative pending approval survives reload without resubmitting the prompt or deciding the approval. See [operator commands and limits](docs/daemon-and-reload.md) and [architecture decision](docs/adr-background-control.md).

The complete normal Windows Rust implementation suite passes 116 tests. Strict Clippy and formatting pass after moving the reload test module; both reload unit regressions are rechecked separately. An earlier standard-process detachment attempt inherited pipes and blocked the caller; only verified fixture-owned workers were gracefully stopped, and the native no-inheritance implementation passes the final tests.

- [x] Unix write ownership and containment review. a host-approved write replaces the file by renaming a temporary file over it, so before this change the new file got the host user's owner and primary group. A test showed a file in a shared supplementary group (`997`) came back as group `1000`, and a world-writable file owned by `65534` became owned by the host user. Now the temporary file gets the existing owner and group with `fchown` before the mode is copied (chown can clear set-id bits). If the host user may not keep them, the write is refused with "cannot keep the existing file's owner or group", the original stays unchanged, and no temporary file is left. Decision (conservative): refuse instead of silently taking over or dropping the group. A root host keeps the original owner. New files stay 0600; extended attributes and POSIX ACLs are not copied. Tests: `unix_replacement_preserves_mode_and_secondary_group` (Linux, uses a supplementary group when the process has one) and the ignored `unix_foreign_owned_target_is_refused_or_keeps_its_owner`. A new Linux CI step prepares a 65534-owned file with sudo on the throwaway runner, runs that test as the runner user (refused) and as root (kept). Both tests failed on the old code locally. The non-root refusal and root paths after the fix were checked only in CI, because local sudo was blocked. Containment tests (outside parents, symlinks, a parent moved after consent, hard links) were already present. Linux passes 98 Rust tests (1 ignored), strict Clippy (Linux and Windows cross-check) and formatting.

- [x] Bound host broadcast retention and waiting callers. journal events are now `Arc<Event>`; the live broadcast carries only `Weak` references through a new `EventReceiver`, so the journal (bounded by history events/bytes) is the sole owner of event payloads. A stalled subscriber can no longer keep up to 256 evicted frames alive (previously up to 256 × max_frame_bytes of deep copies), and an event evicted before delivery is reported as `Lagged`, which the WebSocket path already turns into `reconnect_required` and cursor replay. Requests, notifications and permission answers reserve their encoded size from a per-connection byte budget of max(8 MiB, 2 × max_frame_bytes) before queueing and release it when the actor has handled them; callers beyond it are rejected immediately with a retryable error instead of waiting with their input. `session/cancel` and shutdown are exempt.

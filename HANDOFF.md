8 October 2026 Unix write ownership: a host-approved write replaces the file by renaming a temporary file over it, so before this change the new file got the host user's owner and primary group. A test showed a file in a shared supplementary group (`997`) came back as group `1000`, and a world-writable file owned by `65534` became owned by the host user. Now the temporary file gets the existing owner and group with `fchown` before the mode is copied (chown can clear set-id bits). If the host user may not keep them, the write is refused with "cannot keep the existing file's owner or group", the original stays unchanged, and no temporary file is left. Decision (conservative): refuse instead of silently taking over or dropping the group. A root host keeps the original owner. New files stay 0600; extended attributes and POSIX ACLs are not copied.

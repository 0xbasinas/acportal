# Design screens

The ACP Portal designs were made in Penpot. All 158 boards were exported from it on 18 October 2026 and then deleted from the Penpot page, so **these files are now the design record**.

| Path | What it is |
| --- | --- |
| `png/` | One screenshot per screen, at the design size. **Start here when you need to see a screen.** |
| `html/` | One standalone HTML file per screen, generated by Penpot's markup and CSS generator. |
| `html/index.html` | A viewer: search, filter by size and theme, step through screens with the arrow keys. |

## Finding a screen

File names are the board names, lowercased. `01`–`114` are the numbered boards; the number order is the order they were designed, and a few numbers (96–99) were reused by later boards.

- Mobile boards are 390 × 844; desktop boards are 1440 × 900. Desktop names contain `desktop`.
- Most screens come in a `-dark` and a `-light` pair. Screens `01`–`23` have no suffix and are dark.
- `logo-*` and `50-logo-acp-portal` are the logo boards.

## Viewing the HTML

Serve the folder instead of opening `index.html` from disk, because some browsers and browser tools refuse to load the frames from `file://`:

```bash
cd design/html
python -m http.server 8801
```

Then open `http://127.0.0.1:8801/index.html`. A screen can be linked directly with `#<file name>`, for example `index.html#01-connections.html`.

## Limits

- The HTML is generated: absolutely positioned boxes and inline SVG with no semantic structure. Read the PNG to understand a screen; use the HTML for exact colours, sizes and text.
- Text uses the fonts named in each file's CSS, loaded from Google Fonts. Offline, the browser falls back to a default font.
- Only a few screens were compared against the original Penpot boards. Gradients, images and unusual fonts may differ.
- Nothing here is interactive. Each file is one static state.

## Regenerating the PNGs

The PNGs were rendered with headless Chrome at scale 1, with the frame left-aligned, then cropped to the frame's exact size. Headless Chrome will not open a window narrower than about 500 px, so a 390 px mobile frame has to be rendered in a wider window and cropped; without that the frame is shifted and cut off.
